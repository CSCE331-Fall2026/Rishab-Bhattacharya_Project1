The Structure

This site is built as a small set of static HTML pages with no framework and no build step. Each page is a standalone document, and every page carries the same navigation block so any page can reach any other. That is deliberate: for a site this size, a build pipeline would add more maintenance than it saves.

File Purpose
index.html Landing page — introduction and site overview
activities.html Organizations, involvement, and extracurricular work
portfolio.html Projects and technical work
about.html Longer-form background
genai.html This page — written with AI assistance, styled independently
light.css / dark.css The two swappable themes used by the other pages
functions.js Theme-switching logic

How the Theme Switcher Works

The light and dark modes are not implemented by rewriting styles at runtime. Instead, the stylesheet link in the document head is given an id, and the JavaScript simply repoints its href at a different file: 

<link rel="stylesheet" type="text/css" href="light.css" id="page_style"/>

function dark_mode() {
  document.getElementById("page_style").href = "dark.css";
}

This is the cheapest possible approach. The browser swaps one stylesheet for another and repaints; no element needs to be touched individually, and adding a third theme would mean writing one more CSS file rather than editing any markup.

Why this page ignores the switcher: the toggle only works because it can find an element with id="page_style". This page defines its styles in an internal <style> block and never loads functions.js, so there is nothing for the toggle to grab. The independence is structural rather than enforced by a rule, which is exactly the assignment requirement.

Design Choices on This Page

The palette here is a dark navy with a gold accent, paired with a serif body face and a sans-serif navigation bar. The contrast in typeface between running text and interface elements is a common editorial pattern: it signals which text you read and which text you click without needing extra visual decoration.

What I Would Change Next

Three things stand out. The navigation block is duplicated across every file, so any change means editing five documents — a server-side include or a small generator would fix that. The theme choice does not persist between page loads, since nothing is stored; writing the selection to localStorage and reading it on load would carry it across the site. And the layout is currently fixed-width, so a media query would make it usable on a phone.
